# Переезд панели на новую машину

Одна команда переносит **состояние** панели и приводит новую машину в то же состояние,
что и старая: панель, сертификат, защита хоста, модуль ядра.

```bash
./migrate.sh migrate --to root@NEW_IP --domain newserv.example.ru --stage
```

`--stage` — рекомендуемый режим: новая машина готова, но домен пока обслуживает старая.
Проверил, переключил DNS — поднял Caddy одной командой. Без `--stage` Caddy стартует сразу.

## Что переносится

| Что | Откуда | Как |
|---|---|---|
| серверы, клиенты, ключи, обфускация, приостановленные клиенты | `amnezia/web_config.json` | файлом, права 600 |
| конфиги интерфейсов WG | `amnezia/amneziawg/` | файлами |
| пароль панели, порт, DNS, MTU | `.env` | файлом, права 600 |
| домен и настройки Caddy | `Caddyfile` | файлом |
| nginx (real_ip, 444 сканерам, лимиты) | `nginx/` | каталогом |
| сертификат + ACME-аккаунт | volume `*_caddy_data` | tar внутри бандла |
| блок-лист и источники банов | `/etc/awgsec/` | только с `--keep-security` |
| BBR, nftables, fail2ban, CrowdSec, агент панели | — | **ставятся заново** тем же `install.sh` |
| модуль ядра amneziawg | — | **собирается заново** под ядро новой машины |

Модуль ядра не копируется: `.ko` привязан к версии ядра, чужой не загрузится.
Если сборка не удалась — панель всё равно работает: `awg-quick` уйдёт в userspace
(CPU на пакет выше, но простоя нет).

## Что делает одна команда

1. **Preflight цели** — SSH, docker, compose, свободное место, чистота каталога панели.
2. **Экспорт** — собирает бандл с манифестом и SHA256 каждого файла, права 600.
3. **Перенос** — `scp` бандла на новую машину.
4. **Импорт на цели**:
   - сверка контрольных сумм (испорченный бандл не развернётся);
   - проверка портов (`WG_PORT/udp`, 80, 443);
   - раскладка файлов с правами (600 на ключи, 700 на каталоги с ключами);
   - `--update-endpoint` при необходимости;
   - `install.sh install --with-kernel-module` — хост-защита и модуль ядра;
   - восстановление сертификата Caddy;
   - `docker compose up -d` (или только `amnezia` при `--stage`).
5. **Проверка** — контейнер, nginx, пиры, handshake, модуль ядра, BBR, nft, сервисы,
   свежесть `state.json` вкладки «Безопасность», соответствие endpoint внешнему IP.

Старая машина **не останавливается** никогда — откат мгновенный.

## Главный риск: endpoint в конфиге

Если в `web_config.json` endpoint — **домен** (`newserv.1121440.ru`), переезд прозрачен:
достаточно переключить DNS, клиенты ничего не заметят.

Если endpoint — **IP**, клиенты ходят на старый адрес и после переезда отвалятся.
Скрипт это видит и предупреждает; исправляется флагом:

```bash
./migrate.sh migrate --to root@NEW_IP --update-endpoint auto            # новый внешний IP
./migrate.sh migrate --to root@NEW_IP --update-endpoint vpn.example.ru  # лучше домен
```

## Порядок переключения (режим --stage)

```bash
# 1. развернуть на новой машине, не трогая домен
./migrate.sh migrate --to root@NEW_IP --domain newserv.example.ru --stage

# 2. проверить, что панель живая (внутри машины)
ssh root@NEW_IP '/root/awg-host-hardening/migrate.sh verify'

# 3. переключить DNS на новый IP и дождаться
dig +short newserv.example.ru

# 4. поднять Caddy на новой машине
ssh root@NEW_IP 'cd /opt/my-wg-panel && docker compose up -d'

# 5. убедиться, что клиенты подключились
ssh root@NEW_IP '/root/awg-host-hardening/migrate.sh verify'

# 6. погасить старую
#    на старой машине: cd /opt/my-wg-panel && docker compose stop
```

## Отдельные команды

```bash
./migrate.sh export --out /root/panel.tar.gz              # только собрать бандл
./migrate.sh inspect --bundle /root/panel.tar.gz          # что внутри, без развёртывания
./migrate.sh import --bundle /root/panel.tar.gz --force   # развернуть на этой машине
./migrate.sh verify                                       # проверить текущую машину
```

Полезные флаги `import`:

| Флаг | Смысл |
|---|---|
| `--force` | перезаписать каталог панели (старый сохраняется рядом с суффиксом `.backup-…`) |
| `--stage` | не запускать Caddy (домен остаётся на старой машине) |
| `--no-start` | только разложить файлы, контейнеры не поднимать |
| `--no-host-setup` | не трогать хост (только панель) |
| `--no-kernel-module` | не собирать модуль ядра |
| `--keep-security` | перенести блок-лист |
| `--panel-dir PATH` | другой каталог панели |
| `--dry-run` | показать план |

## Если модуль не собрался

Ничего не ломается: `awg-quick` увидит, что `/sys/module/amneziawg` нет, и поднимется
в userspace (`amneziawg-go`). Панель и туннель работают, но CPU на пакет выше.
Скрипт модуля сразу покажет ошибку компиляции — тогда смотреть:

- `uname -r` и наличие `linux-headers-$(uname -r)`;
- лог `/var/lib/dkms/amneziawg/1.0.0/build/make.log`;
- на новых ядрах API ядра меняется — правится `compat/compat.h` (в скрипте уже
  лежит патч под переходное 7.0.x).

## Частые переезды: что ускоряет

- Бандл маленький (десятки КБ): `web_config.json` + конфиги + сертификат.
- Модуль ядра собирается 30–60 с и кешируется в DKMS — при обновлении ядра
  пересоберётся сам.
- `install.sh` идемпотентен: повторный прогон ничего не ломает.
- Инструменты после импорта лежат на новой машине в `/root/awg-host-hardening`,
  так что `verify` и следующий переезд доступны сразу.

## Домен и сертификат

Сертификат переносится вместе с ACME-аккаунтом, поэтому панель открывается по https
сразу, даже если DNS ещё указывает на старую машину. Продление начнёт работать
после переключения DNS.

## Откат

```bash
# на новой машине
cd /opt/my-wg-panel && docker compose down
# домен вернуть на старый IP
# на старой машине — просто запустить снова
cd /opt/my-wg-panel && docker compose up -d
```

Каталог, перезаписанный с `--force`, лежит рядом: `/opt/my-wg-panel.backup-<дата>`.

## Что НЕ переносится сознательно

- **счётчики трафика** — начинаются с нуля (живут в памяти процесса);
- **логи** nginx — на новой машине свои;
- **состояние fail2ban/CrowdSec** — баны собираются заново (при `--keep-security`
  переносится только ручной блок-лист);
- **модуль ядра** — собирается под новое ядро;
- **секреты в открытом виде** — бандл с приватными ключами имеет права 600 и должен
  быть удалён после переезда (скрипт напоминает команду).
